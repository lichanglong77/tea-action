## 2. 判定：容量不是瓶颈（三种子支持）

| 对比口径 | 结果 |
| --- | --- |
| mAP@0.5 | n 0.983±0.007（区间 0.975~0.988）vs s 0.980±0.008（0.971~0.986），**区间高度重叠**，差 0.35pp < 1σ |
| mAP@0.5:0.95 | n 0.739±0.002 vs s 0.740±0.002，**完全重叠**，差 0.1pp |
| 开销 | n 参数量 3.14M（s 的 28%）、GFLOPs 8.76（31%）、推理 2.53ms（s 的 44%） |

结论写法：**“在 7260 张训练图、6 类有效验证标注的条件下，模型容量不是性能瓶颈：YOLOv8n 与 YOLOv8s 三个种子的 mAP 区间完全重叠（差值 ≤0.4pp，小于种子标准差），而参数量与计算量仅为后者的 28% / 31%，单图推理 2.53ms vs 5.79ms。因此部署采用 YOLOv8n。”**

## 3. P2 消融（相对 A，单种子）

- mAP@0.5 0.971 → 0.977（+0.5pp）；mAP@0.5:0.95 0.735 → 0.731（−0.4pp）；P/R −2.0/−1.5pp；GFLOPs +29%；推理 8.02 vs 5.00ms（+60%）。
- 现在有了种子方差刻度（mAP@0.5:0.95 的 s 三种子 sd = 0.002≈0.2pp），P2 与 A 的 −0.4pp 约为 2σ、仍属边界噪声；但**P2 与 s 均值 0.740 相比低 0.9pp**，且开销明显更高 → 结论仍是“不采用 P2”。
- 写法：**“P2 四尺度头带来的 mAP@0.5 +0.5pp 被 mAP@0.5:0.95 −0.4pp 与 29% 计算量、60% 推理开销抵消；其收益集中于样本极少的白星病（39 实例，+5.0pp≈2 个框），不具统计说服力，故不作为部署结构。”**

## 5. 必须同时声明的两条数据限制

1. **验证集只覆盖 6 个有效类别**：val 1042 实例，分布 Tea Mosquito 585、Leaf rust 280、Red Spider 75、Tea leaf 57、White spot 39、Black rot 6；`Brown blight`(cls1)、`disease`(cls7) 为 0。所有指标只能写成**“6 个有效类别的指标”**。
2. **小样本类别百分点不可靠**：White spot 39 实例，+5.0pp ≈ 2 个框；Black rot 6 实例。仅作趋势参考。
